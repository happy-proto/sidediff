# 性能与资源边界

## 数据读取与并发

Git CLI 负责变更枚举；gix 读取对象与 attributes，difftastic 库直接比较内存字节，省去逐文件 `difft`／`git cat-file`／`git check-attr` 进程及差异内容临时文件。符号链接比较链接目标文本，不跟随读取目标文件。

默认使用 `min(可用并行度, 4)` 个线程，按 Git 原始顺序保留结果。可通过 `SIDEDIFF_DIFF_JOBS` 设置正整数线程数；更多线程会增加工作内存。库内部的语言配置和查询按语言缓存，不在每个文件上重新初始化全部语言。

## 内容准入

在读取内容前查询历史对象头或工作区元数据。环境变量接受非负整数字节数或文件数：

| 环境变量 | 默认值 | 含义 |
| --- | ---: | --- |
| `SIDEDIFF_MAX_FILE_BYTES` | 10485760（10 MiB） | 单个文件任一侧的最大体积 |
| `SIDEDIFF_MAX_TOTAL_BYTES` | 134217728（128 MiB） | 本次获准文件的新旧内容体积总和 |
| `SIDEDIFF_MAX_FILES` | 5000 | 本次最多计算的文件数 |

按 Git 原始顺序分配预算；超限文件保留在列表中，说明省略原因，不读取正文或计算差异。被跳过的文件不占用预算，后续较小文件仍可获准。冲突计入工作区内容；子模块等元数据条目不计内容字节，但仍计文件数。设置零文件数可只浏览元数据。

这些是输入准入限制，不是 RSS 硬上限。算法、解码字符串、JSON、行结构、已保留视图和文件列表元数据仍占内存；文件行数和改动形状也会影响分配。预检后变化的工作区文件不构成固定快照。超过 256 KiB 跳过 kat 高亮，超过 difftastic byte limit 时回退行级 diff，都不能代替整体内存预算。

普通内容通路不物化临时文件；聚合枚举在部分状态下仍会创建临时 Git index。库内的单文件计算仍无协作式中断；取消 TUI 时主动回收 Git 进程组、恢复终端并退出主进程，不再等待库调用完成。操作系统随进程退出清理剩余计算线程。

## 加载诊断

`sidediff --profile` 接受普通比较的全部参数，运行真实加载路径并输出报告，不进入 TUI。`--json` 输出机器可读报告，适合保存、比较和进一步处理；普通比较仍直接使用位置参数，不保留 `profile` 等 revision 名称作为子命令。

- `elapsed_ms`：完整加载的墙钟时间，不包含 TUI 状态初始化或首次绘制。
- `stage_ms`：枚举、对象数据库、大小准入、attributes、文件计算等阶段的墙钟时间。
- `phase_timings`：读取、difftastic、JSON 解码、视图准备、高亮等环节的调用次数、累计时间和最大单次耗时；并行累计值可能超过墙钟时间，父子环节不可直接相加。
- `files`：按耗时降序排列的逐文件记录，包含输入字节数及是否因准入限制省略；文本报告显示最慢 20 个，JSON 保留完整列表。
- `active`：取消或失败时尚未完成的文件及当前环节。Ctrl-c 会保留部分报告，`cancelled` 为 true，退出码为 130；加载错误保留 `error` 并返回非零状态。

可在中途取消以定位长时间占用的文件，无需每次等完整加载结束。进度只写 stderr，stdout 始终用于报告。

如果热点位于 difftastic 的语法搜索，可用 `DFT_GRAPH_LIMIT=100000` 临时降低搜索上限再测。更低的上限会更早回退行级 diff，可能显著降低复杂文件的耗时，但会改变部分差异粒度；它不是保持结果不变的优化，默认值不作调整。

## 测量依据

以下为本地 release 构建的加载基准，包含 Git 枚举、差异计算及显示模型准备，不包含终端首次绘制。库通路基于上游 master 提交 `0b92338c` 重测，使用相同文件快照核对内容与高亮指纹；新版为 4 线程。

| 样本 | 原逐文件 CLI 通路 | gix + 库通路 |
| --- | ---: | ---: |
| 150 个小 Rust 文件 | 13.07 s | 0.29 s |
| 150 个源码样本 | 18.49 s | 1.59–1.69 s |
| 300 个小 Rust 文件 | 24.87 s | 0.43 s |

gix 通路的基准进程峰值 RSS 约为 53、195–208、77 MiB，分别对应上述三个样本，包含结果指纹计算；不是大文件的内存预测或 TUI 完整峰值。另用 1 GiB 未跟踪文件验证准入，文件会被跳过，加载基准峰值 RSS 约 8 MiB。

这些是特定样本的测量，不保证其它仓库的相同倍数。JSON 序列化、显示模型和高亮仍有开销。后续测量统一使用 `--profile` 或 `--profile --json`；线程累计时间及嵌套区间不能直接相加当作墙钟时间。
